# README 文案标准

改 README 前先过一遍本文件。目标：全文一套写法，读者扫一眼就知道哪些是界面上的东西、哪些是说明。

## 1. 界面元素一律用「」，不加粗

界面上能点到、能看到的东西（按钮、菜单项、勾选项、输入框、页面名、提示文字）统一写成「名称」：

- 点击「⋮」→「设置」
- 勾选「开启模拟复制提取」
- 在「岗位描述」输入框中粘贴内容

正文句子里提到界面元素不加粗，首次出现也不加粗。英文的界面选项同样处理：勾选「Allow remote debugging for this browser instance」。

## 2. 加粗的三种用途

1. **条目开头的术语**（冒号前那一个词）：`- **API 地址**：说明…`、`1. **允许非商业使用**：…`
2. **独立成行的粗体小标题**：如「运行中的注意事项」下每一条 `**1. 提取结束前请勿「最小化」Chrome**`
3. **正文里读者要照着做的关键句**：警示（`⚠️ **请勿直接粘贴岗位 JD**。`）、容易踩的坑（`**须填写该密码，而非邮箱登录密码**`）、明确的建议（`**建议在电脑闲置时开启**`）、流程环节名（`① **提取候选人信息** → ② **AI 评分** → ③ **导出 Excel**`）

第 3 类要克制：同一段最多一处，只加在「不照做会出错」或「读者要据此做选择」的地方，别整句加粗。界面元素即使出现在关键句里也不加粗——写「开启模拟复制提取」，不写 **开启模拟复制提取**。

## 3. 条目格式：术语 + 冒号

列表条目统一写成 `**术语**：说明`，说明结尾不加句号。

- 不用「——」连接术语和说明：`- **速度**——约 10 分钟` → `- **速度**：约 10 分钟`
- 破折号只在正文确实需要时用，写成 `——`（不写成 `--`），前后不加空格

## 4. 标点

- 中文语境一律全角：，。：；、？！（）「」
- 引用界面文字、专有说法用「」，不用 “” 或 ""
- 箭头：界面路径紧贴不加空格（「⋮」→「设置」）；流程式的箭头两侧各留一个空格（① 提取候选人信息 → ② AI 评分）
- 并列项用顿号，斜杠分隔的选项两侧各留一个空格（推荐牛人页 / 搜索页 / 沟通页）
- 代码、文件名、命令、模型名用半角并加反引号：`deepseek-v4-flash_DeepSeek`

## 5. 空格

- 中文与半角英文 / 数字之间加一个空格：AI 评分、10 分钟、450 人、第 1 步、Chrome 浏览器
- 中文与标点之间不加空格：下载 `Boss.AI.Setup.1.x.x.exe`，双击…
- 链接与相邻中文之间加一个空格：详细文档见 [CLAUDE.md](CLAUDE.md)
- 品牌名内部不加空格：BOSS直聘、BOSS直聘候选人AI评分助手（应用名）

## 6. 例外

- 代码块、表格、图片 alt 里的内容按原文，不套本标准的标点
- 提示词模板（用户要复制走的）与 `config/scoring-prompt-*.txt` 保持一致，不单独改
- 段落结尾加句号；列表条目结尾不加句号
