# 设计系统（UI 规范）

界面规范的单一来源：颜色、间距、字号、行高、圆角、阴影、焦点环、动效、z-index 一律取自 `electron/renderer/tokens.css` 顶部 `:root` 的「设计 token」。改 UI 只引用 token、不写死数值；改了 token 必须同步本文件对应表格（流程见 §10）。

样式拆成 **6 个 CSS 文件**，`index.html` 中 `<link>` 的排列顺序 = 拆分前的文件内顺序，**勿调换**（否则级联结果变化）。级联顺序的唯一权威是 `index.html` 的 `<link>` 顺序：

| 文件 | 内容（按文件内 `/* ===== 分节 ===== */` banner） |
|---|---|
| `tokens.css` | `:root` 全部 token（字体 / 字号 / 间距 / 色彩 / 圆角 / 阴影 / 焦点环 / 时长缓动 / z-index） |
| `base.css` | reset、滚动条策略、`button` 重置、键盘焦点环、`#app` 页面壳 |
| `topbar.css` | 页头标题与版本号、连接状态容器、左上角菜单、Chrome 状态栏 |
| `config.css` | 首页配置区控件（岗位选择、字段、分段钮、下拉、开关、按钮体系、设置弹窗等） |
| `run.css` | 执行进度步骤条、结果头 / 摘要 / 错误、批量打招呼 |
| `overlays.css` | 弹窗 / Toast / 完成页结果可视化 / 历史记录弹窗 / 全局关键帧 |

> 拆分只是按原顺序「分桶」，不是按功能语义归属——某选择器具体在哪，按各文件内分节 banner 检索，勿按「文件名 = 功能」倒推。

界面逻辑为 `renderer-*.js` **10 个**小文件，按 `index.html` 中的 `<script src>` 顺序引入、共享全局作用域（DOM 引用只在 `renderer-dom.js` 顶部），顺序同样勿调。

## 0. 设计原则

改 UI 前先对照此纲。每条只讲原则，具体数值与做法一律在所指的那一节，**不在这里复述**（复述过的都出现过两边对不上的情况）：

1. **工具优先**：面向 HR 长时间使用的效率工具——密度中等偏紧凑，常用操作一屏放下；鼠标为主、键盘可达。
2. **色彩是语义系统**：色板 = 中性灰阶 + 唯一 accent + 语义色阶 + 档位色阶；颜色一律走 token，无语义挪用、无裸值。accent 是唯一品牌强调色，其余彩色只表达语义或档位。→ §1
3. **层级由尺寸主导**：越大越重要，辅以灰阶与少量加粗；颜色不作唯一层级信号。→ §3
4. **间距走 8 网格**：留白 / 间隙 / 内距与控件**高度**取网格值；控件**宽度**不受网格约束。→ §2
5. **留白与成组**：留白就是层级——重要的东西周围要「空」，宁可空着也不硬塞；分组靠间距、不靠描边线框。→ §2、§6
6. **单列优先**：内容默认一列到底，确有空间与成对语义才多列。→ §6
7. **渐进披露**：核心内容开箱即用；次要内容收进二级入口（菜单）/ 弹窗。→ §6、§8
8. **状态模型完整**：可交互组件五态齐全，按需补 loading / selected。→ §8
9. **键盘可达**：一切交互 Tab 可达，焦点顺序符合视觉阅读顺序。→ §9
10. **状态双通道信号**：任何状态差异除颜色外还要有文字或图标——错误、必选、选中不得只变红 / 只变色。→ §1、§8、§9

## 1. 色彩

色板 = 冷灰 `slate` 系 + 语义色，不混暖灰，分三层：中性灰阶（打底与文字）、语义色阶（accent + 四语义族）、档位色阶（五星 → 一星）。

### 中性灰阶

| Token | 色值 | 用途 |
|---|---|---|
| `--bg-page` | `#ffffff` | 页面底色（纯白）。卡片 `--bg-card` 同为白底 → 两者只靠 `--shadow-sm` 分层；嫌卡片发平就调阴影或给 `.card` 补描边，不要靠底色差 |
| `--bg-card` | `#ffffff` | 卡片 / 弹窗 / 面板底 |
| `--bg-input` | `#f8fafc` | 输入框底 |
| `--bg-subtle` | `#f1f5f9` | 次级底 / 下陷面（只读框、进度条轨道底、分段钮槽底、白面上的悬停底） |
| `--bg-neutral-tint` | `#f8fafc` | 最浅中性底：**只给内嵌徽标**（步骤编号 `.step-number`、步骤徽标 `.step-indicator`，全站仅此两处）。**不承担悬停职责**——它和白底只差一点点，拿来当悬停等于没反应；白面上的悬停底一律取 `--bg-subtle`（见 §8 悬停总则） |
| `--border-card` | `#e2e8f0` | 分隔线、历史行边框（卡片本身不用描边） |
| `--border-input` | `#cbd5e1` | 输入框边框 |
| `--text-primary` | `#0f172a` | 主文字 |
| `--text-secondary` | `#475569` | 次级文字（说明、字段标签） |
| `--text-muted` | `#5f6e84` | 辅助文字（白底 5.19:1、浅灰底 `--bg-subtle` 4.73:1——两处都过 §9 的 4.5）。三代演变：`#94a3b8`（白底 2.9，弃）→ `#64748b`（白底 4.7，达标）→ 现值。最后一次加深是因为它在 3 处坐在浅灰底上（完成页统计标签、只读岗位名、只读输出路径框），而 4.7 那个数是**按白底**校准的，浅灰底上只剩 4.34 |
| `--text-on-accent` | `#ffffff` | 重点色底上的文字 |
| `--color-disabled-bg` / `--color-disabled-text` | `#e2e8f0` / `#94a3b8` | 禁用底 / 禁用字 |
| `--icon-muted` / `--icon-hover` / `--icon-active` / `--icon-disabled` | `#aab6c6` / `#475569` / `#0f172a` / `#cbd5e1` | 图标控件的四态色**阶梯**：静置 → 悬停 → 按下 越走越深，**禁用反向退到更浅**。一行一档，改阶梯只动这四行。用法见 §8「图标控件的状态色」 |
| `--color-scrim` | `rgba(15,23,42,.4)` | 遮罩层 |

### 语义色阶

每个语义族固定「浅底 → 本体 → 深字」三档，规律统一：

| 语义 | 浅底 `--bg-*` | 本体 `--color-*` | 深字 `--color-*-strong` |
|---|---|---|---|
| accent（蓝） | — | `#1a73e8`（**实心底悬停 `--color-accent-light` = `#4285f4`**；白底上的字 / 描边悬停 `--color-accent-hover` = `#1765cc`、按下 `--color-accent-active` = `#185abc`） | 白底上的字取 base（4.51:1，刚过线）；**坐在 accent 浅底上的字取 `--color-accent-strong` = `#1765cc`**（选中态专用——见下方「-strong」说明） |
| success 成功（绿） | `#e6f4ea` | `#34a853` | `#0d652d` |
| warning 警告（黄） | `#fef7e0` | `#fbbc05` | `#a95900`（原 `#b25e00`：在自家浅黄底上只有 4.36:1，四族里唯一不达标的一族，因为它当初是按**白底**校准的。深 5% 后浅黄底 4.76、白底 5.10，两处都过，肉眼几乎无感） |
| error 错误（红） | `#fce8e6` | `#ea4335`（实心底悬停 `--color-error-light` = `#ee675c`） | `#c5221f` |
| info 信息（蓝） | `#e8f0fe` | `#4285f4` | `#1765cc` |

浅底一律**不带描边**（语义提示靠「浅底 + strong 深字」双通道区分，轮廓线交给留白）；故每族只有三档，不设 `--border-success` 之类的语义描边 token。

- **rgb 三元组只用于叠透明度处**：`rgba(var(--color-X-rgb), …)`（滚动条滑块、按钮悬停影 / 状态发光、圆底图标钮的按下底）。**提示条浅底不走这条路**——它有专门的 `--bg-*` 实色 token（见 §8）。
- **base 与 strong 的分工**：色块 / 进度条 / 按钮底用 base；**坐在自家浅底上的文字**必须用 strong，保证对比度。四族（success / warning / error / info）一直都有 `-strong`，只有 accent 缺一档，于是「选中 = 10% 浅蓝底 + accent 字」（§8 定的全站选中态语言）里的字直接取了 base——base 在白底上本就只有 4.51（刚过线），垫一层洗涤后跌到 3.95，成了全站唯一不达标的一族。现已补上 `--color-accent-strong`，选中态的字一律改用它。
- **`-light` 与 `-hover` 方向相反，别混用**：`--color-accent-light` 是 accent **浅一档**，只给「实心底」悬停用（深底变浅）；`--color-accent-hover` / `--color-accent-active` 是 accent **深一档**，给「白底上的字与描边」悬停 / 按下用（浅底加深）。名字里的 `-hover` 指的是「浅底控件悬停」，不是「所有悬停」，看到实心钮想用 `-hover` 时先停一下——那条路走 `-light`。红族同理：`--color-error-light` 给红实心底悬停，红描边钮 / 红字走 `--color-error-strong`。

### 档位色阶（五星 → 一星）

| 档位 | 进度条 / 图形 | 白底档位字 |
|---|---|---|
| 五星 | `--color-success` | `--color-success-strong` |
| 四星 | `--color-accent` | `--color-accent` |
| 三星 | `--color-warning` | `--color-warning-strong` |
| 二星 | `--color-orange` `#f97316` | `--color-orange-strong` `#ea580c` |
| 一星 | `--color-disabled-text` | `--color-disabled-text` |

二星专属橙色只作档位，不作操作 / 警示色；警示一律走 warning 或 error。

### 色彩规则

- 除 `:root` 定义处外，样式表不得出现裸色值；需要新色先加 token 再同步本表。
- 无语义挪用：绿=成功、黄=警告、红=错误、橙=二星，一经建立不再互借。
- 状态不只是颜色（状态双通道）：错误、必选、选中在变色之外另有文字或图标（→§8、§9）。

## 2. 间距（spacing scale）

间距是 **8 网格**：**留白、间隙、内距**（`padding` / `gap` / `margin`）只取 4（半拍）/ 8 / 16 / 24 / 32，不取任意 4 的倍数（12 / 20 / 28 不在网格上，不新造值）。48 / 64 虽在 8 网格上，但全站至今没有一处需要，**没有对应 token、也不要为了「凑完整」加上**。

| Token | 值 | 档位 | 典型用途 |
|---|---|---|---|
| `--space-1` | 4px | 半拍 | 极近邻（图标与字、chip 内距） |
| `--space-2` | 8px | 网格 | 紧凑间隙、列表内距 |
| `--space-4` | 16px | 网格 | 区块间距、面板 padding |
| `--space-6` | 24px | 网格 | 卡片组间、弹窗内距 |
| `--space-8` | 32px | 网格 | 页面级留白 |

**有网格值就先取网格值**；下面两类可以例外，但必须能说清理由。

**一、宽度不受网格约束。** 控件的「尺寸」要分两说：**高度**取网格（40 / 32 / 24 这类），与内距同一把尺；**宽度**由内容与所在栅格决定，网格里也没有够用的档位（最高才 32）。`.input-number` 的 76px 数字框、`.custom-select-trigger` 的 200px 最小宽、`.tip-icon::after` 的 240px 气泡最大宽都属此类，不要试图把它们「四舍五入」到网格上。

**二、由几何反推的内距**：为了让 A 与 B 对齐而算出来的值，改了就会错位。这类值必须写明「由什么反推而来」，否则下一个人会当成随手写的裸值清掉。现存四处：

- `.input-number` 的**左内距 20px**：让数字「居中偏左」而不贴边，且值变长时往左延展、不会顶到右侧的步进箭头（右内距仍是网格值 8）。
- `.count-arrows` 的**列宽 20px**：两个箭头叠在 40px 高的数字框内，列宽只能按框高的一半来配。
- 浮层贴触发器的 `top: calc(100% + 4px/6px)`：`.custom-select-menu` 用 4px、`.menu-panel` 用 6px。
- `.custom-select-menu` 与 `.menu-panel` 的 `gap: 2px`：选项胶囊间的白缝，再宽就不成组。

反过来说：**能用对齐方式（`justify-content` / `align-items`）做到的，不要用负外边距凑**——负外边距会连点击区、悬停底色一起推出内容列，还得多写一条例外。**但有一类负外边距是正当的**：把「撑大的点击区」缩回原占位（`.tip-icon` 的 `margin:-4px`、`.menu-btn` 的 `margin-left:-7px`），此时它缩的是自己多出来的那圈，不会推挤邻居。同类还有 `.settings-body` 的「padding + 等量负外边距」（§4 焦点环）。

**间距同时承担成组**：同组内 4–8、相关组间 16、页面级 24–32。想让某元素重要就放大它周围的间距。

**点击目标**：可点元素高度 ≥24px，下拉 / 弹窗按钮等主要目标 ≥32px。唯一例外是数量步进箭头（`.count-arrow`）：两个箭头叠在 40px 高的数字框内，单个必然 <24px，加高控件才能达标、代价不成比例。它**不是**唯一路径——数字可直接键入，箭头只是快捷方式（Tab 仍可达，见 §9），故不为它破例改控件尺寸。

## 3. 字号与行高（type scale）

| Token | 值 | 用途 |
|---|---|---|
| `--text-xs` | 12px | 最小辅助标签（版本号、徽标）——底线，不可再小 |
| `--text-sm` | 12px | 小按钮 / chips / 徽标 / 只读值 |
| `--text-md` | 14px | 正文、输入框、默认按钮（软件里大多数文字） |
| `--text-lg` | 16px | 模块标题、弹窗标题、主 CTA 文字 |
| `--text-xl` | 18px | 页头标题、完成页标题与统计大数字 |
| `--text-2xl` | 20px | 预留最大档（暂无在用） |

**行高 = 字号 × 倍数**，全站只用四个倍数，且随字号**反着走**——字号越大，倍数越小：字号大了字形整体就高、笔画就密，再给足行间余量整块会散、读着累；字小了反倒需要余量把行分开，否则眼睛容易跳行。所以**标题 ×1.2、正文 ×1.5**。说「越大越小」指的是**倍数**：绝对行高永远随字号变大，缩下去的是倍数——而倍数一收紧，行与行之间的空隙（行距 = 行高 − 字号）自然跟着紧，这是同一条规则的另一面。源码里不再出现行高字面量（行高不受 8 网格约束，见 §2 例外）：

| Token | 值 | 配什么字号 | 角色 |
|---|---|---|---|
| `--leading-tight` | 1.2 | 16–18（标题档） | 标题：页头 / 模块 / 弹窗 / 完成页；大数字 `.stat-value`；编号与统计徽标 `.step-indicator` / `.stat-label` |
| `--leading-compact` | 1.4 | 12–16（单行控件） | 按钮、列表行、下拉项、提示条、步骤状态行 |
| `--leading-normal` | 1.5 | 14（正文档） | 正文：段落、说明、输入框内容、字段标签、框内短提示（错误提示条、空态文案、只读路径） |
| `--leading-loose` | 1.8 | 12（小字长段落） | 长段落：评分理由、结果摘要、确认文案 |

**豁免：单行控件的文字不按字号查表。** 按钮、列表行、下拉项、徽标里的 12–16px 文字都是单行的——单行文字的行间余量看不见，却会直接把控件撑高。它们的行高按「控件高度的一部分」理解，取 `--leading-compact` / `--leading-tight`。**其中 `--leading-compact` 尤其改不得**：按钮高度由它推导，`.btn--sm` 高 27 = 字号 12×1.4 + 上下内距 4×2 + 描边 1×2；改这一行等于改全站按钮高度，§8 里由它推出来的一串几何（图标钮 27 见方、历史行图标间距）全部要重算。**另一头也要防漏写**：`<button>` 的浏览器默认样式用 `font` 简写把行高重置成 `normal`（雅黑下约 1.3，换字体就跟着变），控件上不写行高，它的高度就不受 token 管——分段钮、岗位显示钮、下拉触发器与选项、顶栏菜单项、结果行标题都曾这么漏着。所以**兜底写在 `base.css` 的 `button` 重置里**：元素选择器一次管住所有按钮，将来新加的漏不掉；想另给值的类（`.btn` / `.job-picker-item-name`，给的是同一档）照样盖得住。补上后这些控件各高 2px（分段钮 34→36、下拉触发器 36→38、下拉选项 34→36、顶栏菜单每行 +2；岗位显示钮与结果行标题高度固定 40px，外观不变）。

行高只管单行文字的**垂直余量**：标题基本都是单行，压紧后行框矮 5px——顶栏标题居中撑在固定高度里，整体高度不变；卡片 / 弹窗 / 完成页各矮 5px。「执行进度」那张卡只矮 2px，因为同一行里的灰色小徽标 `.step-indicator` 比标题高，那一行的高度由徽标决定。

（历史：这套值曾经散成 `1.2 / 1.4 / 1.5 / 1.6 / 1.8` 五种字面量、而 token 全站只有 5 处在用，等于规矩没在跑。现收敛为上表四档：`1.3` 归到 1.2、`1.6` 那两处并进 1.5。）

### 字重（两档制）

**只取 400 常规 / 600 加粗**。微软雅黑只有常规 / 粗两档字形：设 500 会被渲染成 400（无中等字形），600 与 700 渲染相同——故 500 档废弃、700 并入 600。

- **400**：正文、提示、字段标签、普通按钮、步骤标题、列表行名、纯值显示——软件内绝大多数文字。
- **600**：只留给真正要强调的地方——标题（页头 / 模块 / 弹窗 / 完成页）、主 CTA（`.btn--cta`）、**分段钮的全部按钮**（注意不是「只给当前项」：`.toggle-btn` 一律 600，选中与否靠底色 + accent 字区分，不靠字重——12px 的 400 与 600 在雅黑下差异太小，不足以承担选中信号）、选中态文字、数字强调（分数 / 统计值 / 步骤号）、岗位选择列表里的**「＋ 添加新岗位」那一行的行名**（它是动作入口、不是一条数据，与该列表的选中行同名同重；曾降到 400，用户定稿改回 600）。
- 加粗用少才有效：需要层次时优先用字号与灰阶（→§0 原则 3），不要靠大范围加粗堆层级。

### 层级公式

- 模块标题 = `lg` / 600：字号字重统一，**颜色分两档**——卡片标题 `.card-title` 用 `--text-secondary`（页面内的模块标签，与下方说明拉开一档但不过黑）；弹窗标题 `.dialog-title` 用 `--text-primary`（弹窗是浮起层，标题要承担「这是哪个弹窗」的识别，比卡片标题再重一档）。同级标题不许一大一小。
- 字段标签 = `md` / 400 / `--text-secondary`：`.field-label`（弹窗内 `.dialog-field label` 同档），标签靠次级色与正文 / 输入值区分。
- 主 CTA = `lg` / 600 / accent 实心（`.btn--cta`，站内唯一且自成一档）；`lg` 只进 ≥40px 高的按钮。
- 一屏内字号档位尽量 2–3 档，别让每个标题都比旁边大一号。

### 字号规则

- 字体默认微软雅黑（`--font-sans`：微软雅黑 UI → 微软雅黑 → Segoe UI），全软件统一，不混第二字体。雅黑只有两档字形，这正是字重两档制的原因。
- 字号收敛为 4 / 2 的倍数，11 / 13px 奇数档废弃。
- 数字数据（分数、人数、进度、统计、步骤号）一律 `font-variant-numeric: tabular-nums`，等宽避免跳动。
- 多行长段落一律两端对齐 `text-align: justify`（候选人评分理由 `.result-item-comment`、岗位描述输入框 `.dialog-field textarea`），短句不必。**单行文本 / 单行输入框不要加**：那一行永远算「最后一行」，两端对齐不会拉伸它，加了也看不出任何变化——软件里除岗位描述外全是单行输入框，所以只有这两处。
- 中文与字母 / 数字间留空格；夹在中文间的英文标点换中文标点。

## 4. 圆角 / 阴影 / 焦点环 / 滚动条

### 圆角

| Token | 值 | 用途 |
|---|---|---|
| `--radius-sm` | 4px | 内嵌小组件（步骤号、徽标） |
| `--radius-md` | 8px | 输入框、按钮、提示条 |
| `--radius-lg` | 8px | 卡片 |
| `--radius-xl` | 12px | 弹窗 |
| `--radius-full` | 999px | 药丸（chips、分段条、状态点、进度条） |

容器取 8（卡片）或 12（弹窗），内嵌小组件取 4；`--radius-full` 只留给药丸类，按钮 / 输入框 / 卡片不用全圆。圆角一律走 token，无非档位值。

另有三个别名 `--radius-card` / `--radius-btn` / `--radius-input`，分别等于 `--radius-lg` / `--radius-md` / `--radius-md`；它们只是「按用途起名」的引用，改档位要改的是被指的原始行。

### 阴影

- 卡片**无描边**，带四向柔和阴影 `--shadow-card = --shadow-sm`（四层 = 底部两层 + 对称两层）：底部「向下 1px 接触线 + 向下 2px 近距漫射」给卡片浮起的方向感（光从上方来，底边必然更实）；再加两层**无偏移**的对称影 `0 0 3px` / `0 0 9px`，专门补给上/左/右 三边。只靠底部两层的模糊外溢，上/左/右 余晕很薄且厚薄不一，卡片会像「只有下边有影」——对称层让 **上 = 左 = 右 浓淡完全相同**，底部因叠了前两层而略实一档。alpha 刻意调淡（`.09/.05/.05/.03`），宁浅勿深——对称那两层比底部再轻一档（.05/.03 vs .09/.05），上/左/右 只是「看得出有影」，不与底部争厚薄。
- 浮起层（弹窗 / Toast）用 `--shadow-md`（别名 `--shadow-elevated`）：偏移与晕影比卡片大一档，层越高影越开。
- **下拉面板（左上角菜单 / 等级下拉）单独一档 `--shadow-dropdown`**：比 `--shadow-md` 明显淡一档（.07/.06）。贴着触发按钮展开的小白面板若用弹窗那档影，在浅色页面上像浮在半空、和按钮脱节。
- 与阴影配套的**浮层描边取最浅档 `--border-card`**（不是输入框档 `--border-input`）：分层交给阴影，描边只负责勾出边界。
- 阴影一律叠「阴影灰」`--color-shadow-rgb: 60, 64, 67` 的 alpha（比纯黑暖而低对比）。
- **唯一例外是「状态发光」**：状态点光晕、accent 选中高光、主 CTA（`.btn--cta`）的 hover 影用语义色叠低 alpha，表达「发光 / 选中」，不是浮起层级。**除主 CTA 外，按钮悬停不再给影**（见 §8 悬停总则：只改底色）。

### 焦点环

- 键盘导航 `:focus-visible` 显示 `--ring-color`（accent .35）+ `--ring-width` 3px 环；鼠标点击不显示。输入框 `:focus` 用更淡的 `--ring-input`（accent .1），config / overlays 各处同取此 token。
- **给滚动容器留环余量，靠的是负外边距、不是 padding。** 聚焦环是**向外**画的 `box-shadow`（spread 3px），而**滚动容器的裁切线是它的内距盒（padding box）**——无边框时内距盒就等于边框盒外缘，所以「给容器加左右 padding」**是没用的**（内距盒不因 padding 向外长），环照样被裁在容器边缘外、看着像被白边抹掉。管用的是给**容器自己**挂等量负外边距：边框盒连同裁切线一起向外撑，内容盒再被 padding 推回原位，子元素位置与宽度一个像素都不动。`.settings-body` 就是这么做的（左右各一档 `padding` + 等量 `margin`）。**内距与负外边距是一对、必须同值**：只改一个就会出现横向溢出、多出一条横向滚动条。
- 一切可 Tab 到的元素必须能看到焦点环。

### 滚动条

- 内容列表框（选岗位 / 候选人 / 岗位描述框 / 设置表单）：平时隐藏，鼠标移入才淡出 5px 细条。
- 主界面整页与历史记录弹窗列表：滚动条一律隐藏，滚轮 / 键盘仍可滚动。
- **「移入才显示」是 CSS + JS 两半，缺一不成。** 颜色/粗细是 `base.css` 的 `:hover::-webkit-scrollbar-thumb`；触发重画的是 `renderer-widgets.js` 里那段「进出框把 overflow 关掉再装回」。原因是 Chromium 不因容器的 `:hover` 变化重画容器自己的自定义滚动条（滚动条独立成层，悬停失效传不进去）：单靠 CSS 样式算得对、屏幕上是旧的，表现为滚动条时有时无。表单控件（岗位描述 `textarea`）的滚动条画在元素自己的绘制里，没有这个毛病，所以它不需要那份 JS——别照着它把 JS 判成多余。

## 5. 动效

| Token | 值 | 用途 |
|---|---|---|
| `--dur-fast` | .15s | 悬停、按下、箭头旋转 |
| `--dur-normal` | .25s | 状态切换、弹窗关闭退场、Toast |
| `--dur-dialog` | .4s | 弹窗遮罩 / 面板进出 |
| `--dur-slow` | .4s | 进度 / 档位条推进 |

缓动：`--ease-out`（.22,1,.36,1）进出场，快进缓出；`--ease-in-out`（.4,0,.2,1）状态切换。

**写 `transition` 时用拼接好的三个 token**，不要自己拼时长与缓动：`--transition-fast`（fast + ease-in-out）、`--transition-normal`（normal + ease-in-out）、`--transition-slow`（slow + ease-out）。全站绝大多数 `transition` 都是 `--transition-fast`（悬停变色一类）。

- 时长只取档位；遮罩与面板**同拍进出**（同一档时长），避免「遮罩先到、面板后到」。
- 只动画 `transform` / `opacity` / `width` 等廉价属性，不逐帧改 `top / left`。
- 循环动画周期不入档位（唯一例外）：`spin` 0.8s、`status-pulse` 1.5s、`step-pulse` 1.6s，周期按观感定、缓动仍取 token。
- **弹窗互切一律走交叉过渡，不留空遮罩帧**：两个弹窗之间跳转必须走 `swapDialogs()`（`renderer-dialogs.js`）——旧卡的遮罩留在原地撑住明暗、面板淡出，新卡以透明遮罩浮上来同步淡入，全程没有「只剩空遮罩」的那一帧。现存两处：目标岗位 ⇄ 添加/编辑岗位（`swapJobDialogs`）、「请选择目标岗位」提示 → 目标岗位（`confirmDialog` 传 `swapTo: { overlay, open }`）。**别写成「先关旧的、再开新的」**：两段淡入淡出之间会露出一帧白底，就是用户反复报的「闪一下」。
- 已内置 `prefers-reduced-motion` 全局降级。

## 6. 布局与容器

### 页面骨架

- 内容列居中且不随窗口横向铺开：`#app` `max-width:720px`、`margin:0 auto`、`padding:16px 40px`。宽度 ≤720 时整列流式铺满，>720 才触发居中（此上限只在超宽窗口生效）。**只要窗口宽度基准 ≤720，内容就不截断、不重排。**
- 首页纵向节奏：状态条贴标题，运行配置卡在其下让开一档 `--space-8` 页面级留白（见 `topbar.css` 该处注释）；运行配置卡内控件行间距 24px。
- 窗口整体缩放：锁宽高比、内容等比（`electron/window.mjs` 的 `lockAspectRatio` + `setZoomFactor`），不用 `transform: scale` 容器或 CSS `zoom`。设计稿内容区 `DESIGN_W/H` 取 8 网格（当前 656×720），宽高比 = 竖长形。

### 单列优先与多列

- 内容默认一列到底；只有成对控件确有空间才并排：`.run-grid`（岗位 / 数量）、`.greet-controls`（等级 / 按钮）、`.results-stats`（四个数字格）。
- `.run-grid` 用 `minmax(0, 1fr) auto`，岗位格占满、数量列按内容收缩；聊天页不选岗位时退化为单列。

### 渐进披露

- 一处可跑通主流程：首屏只有状态条 + 运行配置卡，设置项不占首屏。设置（API / 邮件）与历史记录都是二级入口，收在左上角 `⋮` 菜单下、各自一个居中弹窗；岗位增删改走弹窗；危险操作一律经确认弹窗。
- 分支选项条件出现：勾选「完成后自动打招呼」才显示等级下拉；运行中才出现跳过 / 暂停按钮。

### 弹窗分层

- 叠层按 z-index token：tooltip 100 → dropdown 300 → overlay 1000 → toast 9999。
- 弹窗内容多时只在自身高度内滚动，标题与底部按钮固定。

## 7. 图标

- 固定 **Material Symbols & Icons**（当前版，非 2014 年那套 Material Icons）一套，不混其它图标库。路径取 `material-design-icons/symbols/web/<name>/materialsymbolsoutlined/<name>_24px.svg`，**viewBox 原样保留官方的 `0 -960 960 960`，路径一个字符都别手改**；要实心就取同目录的 `<name>_fill1_24px.svg`（这套的 fill 轴）。
- **实现**：全部画在 `index.html` 顶部 `<symbol>` 库（`currentColor`），用 `<svg><use href="#icon-…"/></svg>` 引用，界面不散落 `<path>`。`<use>` 会把 symbol 自己的坐标系缩放进宿主 svg 的视口，所以**调用处照旧写 `width="16" height="16" viewBox="0 0 24 24"` 就行，不必按 960 换算**。方向箭头用 `icon-chevron-*` 由 CSS `rotate()` 转向，不写字形字符。
- **功能图标统一 outlined（空心）**；实心只留给两类，**别再多**：
  1. **媒体控制三件套** `icon-play` / `icon-pause` / `icon-skip`。这三枚在 Material 里**没有可读的细线形**（播放三角、暂停双杠本身就是实心几何），取 outlined 只会得到细线描边，14px 下糊成一团 —— 故取 `_fill1_` 那版。它们**不代表强调**，只是字形如此。
  2. **CTA 强调**（`.btn--primary` 一类）：这里实心才真的是「比旁边重一级」的信号。
  判断标准是「这枚字形有没有能看的细线版」，不是「它重不重要」。要新加实心图标，先确认它落在上面两类里，并在取用处写明理由。
- **尺寸只有六个值：12 / 14 / 16 / 18 / 20 / 28。** 每档绑死一个角色，取用时按角色选，不按「看着差不多」：

  | 档 | 尺寸 | 角色 | 判定标准 | 现在用它的地方 |
  |---|---|---|---|---|
  | 微 | **12** | 纯指示 | 本身不可点，**所在容器**才可点 | 下拉箭头、结果行展开箭头、邮件失败箭头 |
  | 小 | **14** | 行内 | 旁边有文字陪着的按钮内图标；或本身就是个小可点控件 | 运行区 / 结果页按钮内图标、数字增减箭头、暂停/继续 |
  | 中 | **16** | 内嵌图标钮 | 嵌在别的控件里，或旁边是**更小**的控件 | 输入框内的图标钮（提示 ℹ️ / 眼睛 / 清除 × / 文件夹） |
  | 大 | **18** | 独立图标钮 | 自占一格，周围**没有**更小的控件 | ⋮ 菜单项图标（设置 / 历史记录）、页头 ⋮、历史记录行的无框图标钮（垃圾桶） |
  | 大⁺ | **20** | 独立图标钮 · 墨迹对齐值 | 同上，只给墨迹占比偏小的图标用（见下方「墨迹微调」） | 历史记录行的无框图标钮（文件夹） |
  | 特大 | **28** | 状态大图标 | 装饰性，不是控件 | 结果页成功勾 / 失败叉 |

  **两处不在表里**（写在这里是免得下一个人照表或照自检第 17 条把它们「改回」档位内的值）：
  1. 岗位描述框的拖拽手柄 `.textarea-resize-handle`（`icon-resize`，12px）。图标尺寸落在「微 12」那一档，但**它自己就是控件**（拖它改高度），不适用「纯指示 · 本身不可点」那条 —— 它按下面「点击目标不小于 24×24」走（盒子 24×24 且贴角，图标墨迹位置一像素没动，见 `overlays.css`）。**它只有鼠标一条路**：`<textarea>` 的高度本来就不能用键盘调，这是浏览器的既定行为，不是漏了键盘支持（原生 `resize` 手柄同样如此）。
  2. 气泡尖角 `.tip-arrow`（`icon-arrow-drop-down`）的 svg 盒取 **28.8** —— 它不是一个「图标项」，是贴着气泡的装饰几何，进不了「角色」那列；28.8 也不是档位，而是**放大倍数**：这枚字形的墨迹只有 10 宽 5 高，按 1.2 倍放大后包进 28.8 的盒子，露出来的墨迹才正好是那枚 12×6 的三角。按 12 或 28 写都会把尖角改错（墨迹缩水或涨出去）。
  **图标与文字间距取 8px**（`.btn` / `.menu-item` / `.custom-select-trigger` 的 `gap`，也是新写时的默认）。三处收成 4px，都是「图标紧贴文字看」的场合：运行区那三个按钮 `.running-actions .btn`、邮件失败原因的展开箭头 `.mail-error-details summary`、「开启模拟复制提取」与其右侧 ℹ️ 的 `.copy-opt-group`。
- **为什么标称尺寸普遍比文字大一号**：按 24 格归一化后，Material 的图标墨迹只占 16~18 格，四周自带约 2 格留白。所以标称 14 的图标墨迹才 10.5~12px，正好与 12~14px 文字齐平。数着「14 的图标配 14 的字」觉得别扭时，先想起这条。
- **墨迹占比明显偏小的图标，允许在同一档内 ±2 微调**，目的是让同一行里的几枚图标「墨迹等高」，而不是 svg 盒等高。已知的唯一一处：历史记录行的两个无框图标钮——垃圾桶墨迹**高** 18/24、文件夹只 16/24，同一尺寸下垃圾桶明显大一圈，故垃圾桶取 18（18×18/24 = 13.5 墨迹高）、文件夹取 20（20×16/24 = 13.3 墨迹高），两者墨迹等高（约 13.4px），与同行 12px 按钮文字的墨迹也大致齐平。**判断用「高」不用「宽」**：垃圾桶墨迹是 16 宽 × 18 高、文件夹 20 宽 × 16 高，宽高并不相等，只有高度是齐的；横向那对数字与随之而来的间距补偿见 §8「按钮排列」。**这类微调要写明理由**，否则下一个人看到同一行两个尺寸会当成没做完。
- **菜单项、下拉项这类「行」不受按钮比例约束**：行有整行的高度和留白可用，图标取 18（与页头 ⋮ 同档）比取 16 更清楚。只有**按钮内**图标要守 §8 的比例（≲ 字号 1.1×）——那是图标与文字挤在同一个控件里的场合。
- **点击目标不小于 24×24**：图标可以只有 12~18，但可点区要撑到 24（§9）。两种撑法，看该元素周围要不要留白：`.field-icon-btn` 直接就是 24×24 的盒子（图标居中）；`.tip-icon` 盒子同样 24×24，但**配 `margin:-4px` 把占位缩回 16**，视觉位置与间距一动不动、四周各多出 4px 可点区（与 `.menu-btn` 用负外边距把 32 的悬停底框对回字形中心是同一手法）。**浮层要锚在盒子「中线」而不是边缘**：图标在盒内居中，中线与盒子尺寸无关，`bottom: calc(50% + 16px)` 这类写法在盒子改成 20 / 28 / 32 时都仍然正确（`.tip-icon` 的气泡与尖角就是这么写的）。锚边缘（`calc(100% + 4px)`）则每次改盒子高度都要重算一遍——这个坑踩过一次。
- **颜色与状态色**：跟随 `currentColor`；图标控件的四态取自 `--icon-*` 四行（定义在 `tokens.css`），**只加深、不变色相、不用 `opacity` 表达「淡」**——全站已无一处这么做。完整规则见 §8「图标控件的状态色」。
- **图标控件目前一律不带语义色**——理由见 §8「图标控件的状态色」。
- **图标与中文同一行时，垂直方向对齐文字的「墨迹中线」，不能只靠 flex 盒子居中**：中文在字体行框里比中线低约 0.035em（14px 字号 ≈ 0.5px），只做盒子居中会让图标看着偏高半像素，齿轮这类上下对称的图标最明显。做法是给该行图标半个像素的光学补偿（`.menu-item svg` 的 `translateY(0.5px)`，按 0.035em 随字号走），不是把图标盒撑高、也不改行高。
- `icon-resize`（岗位描述框拖拽手柄）是全站唯一内联画线：两条 45° 斜线平行、短线收在右下不越出长线，保持该几何。它不是 Material 图标，故不走上面那套路径来源。
- **气泡尖角用图标库那枚 `arrow_drop_down`（`.tip-arrow`），不手画几何**：它墨迹 10 宽 5 高、两条腰正好 45°，调用处按 **1.2 倍**放大成 12×6 的尖角（盒子 28.8 的来龙去脉见上面「两处不在表里」第 2 条）。
- **记一笔：45° 斜边「左右不对称」是浏览器光栅化的问题，跟手画还是图标无关；但偏移量的零头会改变它偏在哪一侧、偏多少。** 用路径画（图标 `<svg><use>`、`clip-path`、`border`），同一条斜线的左右两侧会落在不同的**设备像素相位**上，实测同一行「两侧过渡像素覆盖率之和」能差 0.17~0.20（表现为左腰比右腰胖一丝、与气泡左侧的衔接发假）；`border` 因为宽高被吸到整设备像素上反而左右一致（0.50 / 0.50），代价是与不吸附的气泡错开 0.27px、接缝漏白线。**这个偏差对定位的零头极敏感**：尖角原先手写 `left: calc(50% - 14.4px)`，量到左 0.52 / 右 0.69；改成 `left: 50%; transform: translateX(-50%)`（偏移 -14.397px，与 14.4 差 0.003px）后，两条腰落在互为镜像的相位上，实测**左右各 0.61、差 0.00** —— 同一个图标、同一套样式，只差这零点零零几像素。所以：① 报「左右不对称」前先把偏移量挪个零头再量一次，别急着换画法；② 改尖角的居中式（`left` / `transform` / 盒子尺寸）都要照 §7 的量法复测，它可能把偏差挪回来。真想不依赖相位、**严格**左右一致，只有**渐变遮罩**一招（`linear-gradient(45deg,…)` 切左腰 + `linear-gradient(135deg,…)` 切右腰、`mask-composite: intersect`，两端过渡带取等宽；实测差 0.00）—— 它是纯装饰几何的正当选项，「图标只从库里取」那条管的是有语义的图标控件，不覆盖尖角这类形状。

## 8. 组件约定

### 状态模型总纲（五态底线）

任何可交互组件都要定义完整状态组：`rest` / `hover` / `active` / `focus-visible` / `disabled`（禁用 = `--color-disabled-*` + `cursor:not-allowed` + 去阴影），按需补 `loading` / `selected`。

- **按压反馈两类**：可整体缩放的控件（按钮）按下 `scale(.97–.98)`；行级元素（整行、下拉项、菜单项）用按下底色，不整体缩放。**分段钮是具名例外：按下不缩放**（原 `scale(.97)` 已按用户要求删除），它的按下观感就是「指针正压住的那一格」——未选中的格子铺**选中档 10%**（按下 = 选中档，与下拉 / 列表行 / 菜单项同一条；若照抄悬停那 5% 则按下去毫无变化），已选中的格子保持 15%。这两条**由 JS 挂的 `.is-pressed` 类承担，不能靠 `:hover`**：分段条一旦开始拖动就会捕获指针，而 Chromium 在捕获期间把 `:hover` 归给捕获元素，按钮自己的悬停会整个失效——真机按住几乎都会抖过 4px 阈值、算成拖动，靠 `:hover` 的话「按住时那层颜色」会凭空消失（用户两次反馈：先是不见 5% 淡底，后是「按住颜色变深没了」）。所以它实际是 rest / hover / selected 三态（分段钮没有禁用态，JS 从不置 `disabled`），`active` 与 `hover` 同观感，这是有意的，别再补一条按下反馈回去。
- **loading**：按钮加载 = 前置转圈动画 + 真正的 `disabled`（置灰、鼠标键盘都点不动），**文字保持不变**——不改成「正在… / …中」。转圈由 CSS `.is-loading::before` 提供，JS 侧统一用 `setLoading(btn, bool)` 开关：它记住进入加载前的禁用状态、结束时还原，可与按条件禁用叠加。
- **selected**：选中态 = 底色 + accent 字双信号（→§9）。

底色约定：输入框用浅灰 `--bg-input`，下拉 / 选择框与卡片用白 `--bg-card`。

### 悬停总则：浅底加深、深底变浅

（适用于**所有**有底色的可点面：按钮、下拉项、列表行、菜单项。）

- **只改底色，不上浮、不加悬停影**。原先每个按钮悬停都 `translateY(-1px)` 上浮，再叠各变体自己的底色变化与阴影，结果是「有的在变色、有的在动」，观感杂。统一成同一种语言：**底色浅的（白底、透明、浅色洗涤）悬停加深一档；底色深的（实心 accent / 实心红）悬停变浅一档**。这是专业设计系统里最常见的做法（浅面上叠深色状态层、深面上叠白色状态层，方向相反），好处是「悬停＝更醒目」这个直觉在两种底色上都成立，不需要用户去分辨这排按钮是哪一档。
- 具体取值：实心 accent `--color-accent` → `--color-accent-light`（浅一档）；实心红 `--color-error` → `--color-error-light`；白底描边钮 → 5% accent 淡底 `--bg-accent-tint`；透明幽灵钮 → 下陷面 `--bg-subtle`（**不是 `--bg-neutral-tint`**，那档在白卡上几乎看不出，等于悬停没反应）；红描边钮 → `rgba(--color-error-rgb, .10)`。**白底上的字 / 描边**（`.custom-select-trigger:active` 这类不是整块底色的）走 `--color-accent-hover`（方向与实心底用的 `--color-accent-light` 相反，见 §1）。
- **按下不再单独给色**，统一交给 `.btn:active` 的 `scale(.98)`。少了按下的深色，但避免了「悬停变浅、按下又变深」的方向来回；按压反馈由缩放承担（见上「按压反馈两类」）。**唯一的例外还是主 CTA**，见下条。
- **无底色的图标类控件不走这条**——它没有底色可改，改用下面那条独立的色阶。两者的关系是：**有底色的改底色，没底色的改自身颜色**，都是「往更醒目的一档走」。
- **唯一例外：主 CTA「开始提取分析」**（`.btn--cta`）。它是全站唯一的大实心按钮、主流程的起点，保留原来的「上浮 + 加深 + 悬停影」，让「按这里」的引导力跟其它按钮拉开：它悬停是**加深**（`--color-accent-hover`），方向与常规实心钮相反。
- **它自成一档，不叠 `.btn--primary`，也不叠尺寸类。** 早先的写法是 `.btn--primary.btn--lg` 再靠**双类提权（0,5,0）**去压 `.btn--primary:hover`（0,4,0）—— 压是压得住，但那是权重战争：变体一挪位、或者谁再给它加一个类，就会悄没声地失效。现在 accent 实心底 + 大号尺寸 + 自己的三态全写在 `.btn--cta` 一个类里（都是 0,3,0），不压任何人。**`--lg` 尺寸类已随之删除**：全站只有这一枚大号按钮，留一个「大号」档却没有第二个用户，只会让人以为可以随手加上。
- **它的按下也保留了单独底色**（`--color-accent-active`，比悬停再深一档），这是上面「按下不再单独给色」的同一处例外：它悬停本就朝「加深」走，按下再深一档是同方向的第三步，不会出现「变浅又变深」的来回。**两条例外都只属于这一枚**，别的按钮不要照搬——照搬就会出现「同一个界面里有的按钮按下变深、有的只缩一下」的不一致。

### 图标控件的状态色

（适用于**所有**「一枚图标自己就是个控件」的地方：数字增减箭头、提示 ℹ️、密码显示 / 隐藏、输入框清除 ×、输出目录文件夹、页头 ⋮、历史记录行的无框图标钮。）

四态都从**同一条灰阶阶梯**取。阶梯自己是一组 token，**定义只在 `tokens.css` 那四行**（与 accent 洗涤三档同一手法），组件只引用、不写字面量：

| 态 | Token |
|---|---|
| 静置 | `--icon-muted` |
| 悬停 | `--icon-hover` |
| 按下 | `--icon-active` |
| 禁用 | `--icon-disabled` |

（色值不在这里复述，见 §1 中性灰阶表的 `--icon-*` 行——阶梯改值时只动 `tokens.css` 那四行与 §1 那一处，两处是「定义 + 引用」的关系。）

- **方向：静置 → 悬停 → 按下 越走越深，禁用往反方向退（比静置更浅）。** 这一条容易写反：禁用是「退到后面去」，若顺手借了更深的灰（早先借过文字的 `--color-disabled-text #94a3b8`），禁用态会比静置态**还醒目**，只能再压一层 `opacity` 去补救——那是把补丁当设计。用 `--icon-disabled` 之后全站再无一处用 `opacity` 调淡。
- **只加深，不变色相**。历史上「输出目录」的文件夹钮悬停会把灰色**变成蓝色**（`--color-accent`），是全站唯一变色相的图标，已并入这条阶梯。
- **整族共用一个底座**：输入框内那三个（眼睛 / 清除 × / 输出目录文件夹）本就共用 `.field-icon-btn`，阶梯就写在它上面，变体只写自己独有的东西（清除 × 只写那圈浅灰圆底）；无框图标钮 `.btn--icon` 自带四态色、不搭配任何变体。**新增一个图标控件时不要重抄这四档**——要么挂进已有的族，要么引用那四个 token。
- **图标不带语义色**：历史记录行的垃圾桶曾经是红的（`btn--danger-ghost`），现已与旁边的「打开目录」统一为灰。图标控件里不再有第二个色相，**「这是破坏性操作」改由图标字形（垃圾桶）+ 动作时的确认弹窗承担**，不靠颜色预警。若将来确有需要上语义色的图标，必须写明理由并同步本节——否则它就成了那条阶梯上唯一的例外，读起来像没做完。
- **底色层与色阶是两件事，可以并存**：页头 ⋮ 悬停除加深字色外还铺 `--bg-subtle`，输入框清除 × 悬停铺一圈 18% 灰圆底——那是「这个控件自己占一块方形点击区」的表达；而内嵌在其它控件里、只是个记号的小图标（数字增减、ℹ️、历史行图标钮）**只加深不铺底**，免得跟所在控件抢视觉。判断标准是**它有没有自己的方块点击区**，不是它叫什么。
- 注意 `.menu-btn[aria-expanded="true"]` 的蓝色不在这条阶梯里：那是**展开态**（选中语义，见上「selected」），不是悬停。

### 组件速查表

（逐组件的状态要点与关键规范。上面三节是**通则**，先读通则再查这张表。表里只写这张表独有的信息，通则已覆盖的不复述。）

| 组件 | 状态要点 | 关键规范 |
|---|---|---|
| **按钮** `.btn` | rest / hover（**浅底加深、深底变浅**，只改底色，不上浮不加影）/ active（scale .98）/ focus-visible / disabled / loading | 变体按层级：`primary`（accent 实心，主 CTA）→ `secondary`（蓝描边）/ `ghost`（灰描边，次操作）→ `danger`（红实心，仅确认弹窗破坏位）/ `danger-ghost`（红描边）/ `warning` 与 `paused`（琥珀浅底 + warning 描边，运行区的「跳过提取」「暂停」，两者同款）。另有 `link`（链接式小按钮，白底 + 12px 字 + 更小内距）与 `retry`（失败重试，悬停才转红）。**描边钮一律描边与文字同色**（secondary 蓝、ghost 灰、danger-ghost 红），不允许「灰描边 + 彩字」的混搭。`danger-ghost` 目前只有「清空历史记录」在用；历史记录行内的删除钮不走它——那两个图标钮都是灰的（见 §8「图标控件的状态色」）。尺寸 `btn--sm/block`；文字常规 400，仅 `.btn--cta` 加粗 600。比例与排列见下方两节。 |
| **纯图标钮** `.btn--icon` | 同 `.btn`，但配色自成一套 | 把 `btn--sm` 的横向内距换成边长 27 的正方形（= 同一行文字钮的高度，由 `.btn--sm` 的字号 12 × 行高 1.4 + 内距 4×2 + 描边 1×2 反推；改 `--sm` 这几个值要同步重算）。**自带四态色、不搭配任何变体**——底色与描边一律 transparent，所以不要给它叠 `btn--ghost` 之类带描边的变体（会冒出一个方框）。图标尺寸按墨迹等高定，见 §7「墨迹微调」。**必须带 `aria-label`**、**不要给 `title`**（原生 title 会弹系统气泡，是用户明确要去掉的）。 |

| **下拉 / 分段钮 / 开关** | 五态；选中态 accent | 原生 `<select>` 在 Electron 部分场景打不开 → 下拉统一用自研 `custom-select`，任何情况可展开。**菜单展开时箭头一律 `rotate(180°)`**（打开即翻转，不跟随菜单是朝上还是朝下——`renderer-widgets.js` 有注释说明为何不再跟随方向）。分段钮 `toggle-group`：槽底 = `--bg-subtle`（下陷面，**不用 `--bg-page`**——`--bg-page` 与 `--bg-card` 现在是同一个色 `#ffffff`，槽的轮廓在白卡里完全看不见）；选中 = 浅蓝底 `rgba(accent,.10)` + accent 蓝字（轻量选中态，不与主 CTA 实心蓝撞车）。勾选类开关（含「开启模拟复制提取」的 `.copy-opt-group`）用原生 checkbox + `.checkbox-label`，标签包着控件、不写 `for`。accent 洗涤固定三档 `5 / 10 / 15`（悬停未选中 / 选中·按下 / **悬停已选中**），档间恒差 5，取值只在 `tokens.css` 三行里改；其中选中档 `.10` 是本节定值，不随同批调整。**按下与选中同色**——下拉 / 列表行 / 菜单项 / 候选人行的按下底色一律取 `.10`，不取第三档：按下即预览「松手后会变成的样子」，而 `.05` 一步跨到 `.15` 是跨两级、跳得太狠（用户反馈偏深）。第三档 `.15` 只用于「悬停一个**已经选中**的项」（`.selected:hover` 一类）。**分段钮不走这条**：它按下不另加底色——「压住的那一格」自己承担观感（未选中按下 = 选中档 10%、已选中 = 15%，`.is-pressed`），见 §8「按压反馈两类」。 |

### 按钮与内文字比例

按钮「身高定字号」，文字不「撑」按钮：

| 按钮 | 高 | 内文字 | 字号/高 |
|---|---|---|---|
| `.btn--sm` | ≈27px | `sm`(12) | 0.44（最小钮，允许） |
| `.btn` 默认 | ≈36px | `md`(14) | 0.39 |
| `.btn--cta` | ≈40px | `lg`(16) | 0.40（上限） |

- `xl`(18) / `2xl`(20) 不进按钮；想让字更大 → 加按钮高度，不是把字塞进矮按钮。
- 按钮内图标**墨迹高** ≲ 字号 1.1×，与文字 gap ≥4px。（比的是**墨迹**不是盒子：Material 的 24 画布自带约 2 单位留白，盒子 18 / 20 的墨迹高才 13.5 / 13.3，正对 12px 文字的 1.1×。按盒子边长去卡这条会把 §7 墨迹微调过的图标判成超标，反过来会把它改小。）

### 按钮排列：鼓励靠右、危险靠左

- 普通动作（保存 / 确定 / 开始）：主动作放最右，取消在左——如新岗位弹窗「取消 → 保存」。
- 危险动作（删除 / 清空历史）：放**偏左**，与主 CTA 拉开、被推离惯用点击区，也符合「主 CTA 靠右」；危险确认弹窗里「取消」即鼓励动作，放右侧合理。（「偏左」不必然是第一个——历史记录行按用户指定的顺序把删除放在第二位。）
- 鼓励动作视觉更实（primary 实心蓝），不与危险按钮做对等的对称样式。
- **历史记录行是本节的具体例子**，按钮顺序固定为 **继续提取 → 删除 → 打开目录 → 评分**：两端文字钮、中间两个纯图标钮（删除 / 打开目录），视觉呈「文字-图标-图标-文字」对称；评分实心、靠最右（主 CTA 靠右），删除位置偏左（避开惯用点击区）。它的两个图标钮是灰的（无框，见 §8「图标控件的状态色」），间距取 `--space-1`(4)（一排控件本就少，4px 排得紧凑不散）。
- **但间距是「盒子相等」，视觉上并不相等**：图标钮的可点区是 27 见方的框、墨迹只占中间一块，左右各剩多少空白要看那枚图标的墨迹**宽**（垃圾桶 18px svg × 墨迹宽 16/24 = 12.0 → 左右各空 7.5；打开目录 20px svg × 墨迹宽 20/24 = 16.7 → 左右各空 5.2）；而接在它后面的实心 / 描边钮，其盒边就是视觉边。同为 4px 框距，「图标 → 实心钮」只剩 4 + 5.2 ≈ 9.2px（显挤），而「图标 → 图标」有 7.5 + 4 + 5.2 ≈ 16.7px（显松）。故两条各校正一档：`.btn--icon + .btn:not(.btn--icon) { margin-left: var(--space-1) }` 补一档、`.btn--icon + .btn--icon { margin-left: calc(-1 * var(--space-1)) }` 收一档，补完三种交界是 11.5 / 12.7 / 13.2，全落在 12±0.7px 内（`margin` 而非改 `gap`，因为只有这两处交界需要校正；`:not()` 不能省——图标钮自己也是 `.btn`）。
- **当前批次不能删除，但按钮照常占位走禁用态**：只删按钮会让每行末端结构不一致、图标位置来回跳，禁用理由写进 `aria-label`（不给 `title`），不让用户猜。

## 9. 改完自查

改完 UI 照这份清单过一遍。前七条是无障碍底线（改动不得让它退化），后八条是设计系统一致性。

**无障碍底线**

1. **对比度**：正文与重要标签 ≥4.5:1，大字号 / 粗体可放宽到 3:1。已校准：正文 `#0f172a`、次级 `#475569`、辅助 `#64748b`（≈4.7:1）达标。
2. **键盘可达**：全部交互 Tab 可达并用 Enter / 空格 / 方向键操作；弹窗内 Tab 循环、Esc 关闭。
3. **焦点顺序**：Tab 遍历顺序与视觉阅读顺序一致（自上而下、自左而右）。
4. **焦点可见**：键盘导航显示 `--ring-color` 环；鼠标点击不显示；切换页面时程序聚焦的定位标题 / 弹窗（`tabindex=-1`、非交互控件）只是读屏落点，不画环。
5. **不只靠颜色**：错误 = 红描边 + 提示文字 / 图标；必选 = 标识 + 校验提示；选中 = accent 底 + accent 字；连接状态点 = 颜色 + 文字。
6. **读屏**：纯图标按钮有 `aria-label`；装饰图标 `aria-hidden`；展开收起用 `aria-expanded`；动态提示用 live region；弹窗 `role=dialog` + `aria-modal`。
7. **文字可选中**：正文默认可选中复制，仅交互元素 `user-select:none`。**动效可关**：尊重 `prefers-reduced-motion`。

**设计系统一致性**

8. 颜色全走 `tokens.css` token（`var(--…)` 或 `rgba(var(--color-X-rgb), …)`），无裸 hex / rgb。
9. 间距在 8 网格上、取 `--space-*`，无自造值（例外见 §2）。
10. 字号在 type scale 内，正文 / 辅助 ≥12px；字重只在 400 / 600 里取；行高 = 字号 × 倍数，按 §3 那张表取（标题 ×1.2 / 正文 ×1.5 / 小字长段落 ×1.8 / 单行控件 ×1.4），无自造行高字面量，单行控件不漏写。
11. 圆角 / 阴影 / 焦点环 / 动效用了对应 token 与档位；`transition` 用 `--transition-*` 而不是自己拼时长。
12. 可交互组件五态齐全，行级控件有按下底色。
13. 悬停遵循总则：有底色的改底色（浅底加深 / 深底变浅、不上浮不加影），无底色的图标改自身颜色（见 §8 两节）。
14. 图标类控件取了 `--icon-*` 四态 token（禁用档比静置**更浅**），**没有**重抄色值、也没有用 `opacity` 调淡。
15. 状态差异双通道：不只靠颜色。
16. 单列优先未被破坏；按钮排列：主动作靠右、危险靠左，一卡只一个实心 primary，按钮文字 ≤ 身高 ~40%。
17. 图标沿用 `<symbol>` 那套、`currentColor`；尺寸在 12 / 14 / 16 / 18 / 20 / 28 六个值内（§7「两处不在表里」登记的两个例外除外）；无 Emoji / Unicode 字符当图标（档位星号 `★☆` 除外，见 §7）。
18. 中文标点与用词和界面其他地方一致。
19. 改了 token 已同步本文件对应表格；改动涉及用户可见界面则同步 README 截图（先给用户确认）。
20. `npm start` 目测新旧状态切换。

## 10. 新增 / 修改一个 token

1. **先查旧的有没有人用**：加新 token 前 grep 一遍同类旧值，有替换关系就连旧的一起删（本文件也一并更新）。留着没人用的 token 会让下一个人以为它还在生效。
2. 在 `tokens.css` `:root` 加值并注释用途；
3. 同步本文件对应表格；
4. 语义色补齐整套（浅底 / 本体 / 深字，需要叠透明度再补 rgb 三元组）；
5. 替换引用处、删旧裸值，`npm start` 目测确认。
